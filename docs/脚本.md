# 脚本

moban 独立维护时，用本目录脚本上传皮文件、创建/更新组件和页面。不要依赖仓库外的临时 `.mjs`，也不要把 token 写进 git。

相关：资源路径见 [流程与步骤.md](./流程与步骤.md) 1.3；页面 type / 固定页码见 [page契约.md](./page契约.md)；组件 `type` 见各 [契约-组件类型](./契约-组件类型/)。

---

## 1. 位置与依赖

```
moban/
  website/{type}/{code}/{html|css|js|md|media}/
  scripts/
    config.json      租户 id 与 API 地址（无 token）
    upload.mjs       上传 website/
    cms.mjs          组件 / 页面 / 关联
    lib/
  .env               本地 token（已 gitignore）
```

只需要本机 Node（与 `package.json` 的 `engines.node` 一致）。在 **moban 根目录**执行：

```
node scripts/upload.mjs --help
node scripts/cms.mjs --help
```

或：`npm run upload -- --dir website/static/hero01`、`npm run cms -- component list`。

---

## 2. 鉴权

写操作（上传、创建、更新、删除、关联）需要 JWT。按优先级：

1. 环境变量 `GT6_TOKEN`（或 `GT6_API_TOKEN`）
2. `moban/.env` 里的 `GT6_TOKEN=`
3. 若仍在 35 套模板仓库里，可回退读上一级 `ID和token.md` 的 `moban` 行

`scripts/config.json` 只放 `tenantId` 和接口基址。**不要**把 token 写进 `config.json` 或脚本源码。

复制 `.env.example` 为 `.env`：

```
GT6_TOKEN=
# GT6_TENANT_ID=c36a188f-9971-4304-8659-f8048451fb2c
```

租户默认即 moban 库租户（与 `src/config/app.ts` 一致）。覆盖用 `GT6_TENANT_ID` 或改 `scripts/config.json`。

list / get 读 `https://gt6json.shopasb.io/tenant_{id}/…`，可以不带 token。

## 3. 上传 `upload.mjs`

把本地 `website/` 拷到 tenantdoc。存储 key：

```
{租户id}/website/{type}/{code}/{资源类}/{文件名}
```

公网 URL：`https://tenantdoc.gt6ai.xyz/` + 该 key。文本走 `upload-from-content`，并带正确 MIME（`text/css`、`text/html` 等，不用 `octet-stream`）。图片/字体走 `upload`。

```
node scripts/upload.mjs --dry-run
node scripts/upload.mjs --dir website/static/hero01
node scripts/upload.mjs --file website/layout/theme01/css/theme01.css
node scripts/upload.mjs --dir website/static/hero01 --kind css,html
```

| 选项 | 说明 |
|------|------|
| 无路径 | 上传整个 `website/`（含 `vendor/`，本项目是库租户） |
| `--dir` | 该目录下全部文件 |
| `--file` | 单个文件 |
| `--kind` | 只上传 `html` / `css` / `js` / `md` / `media`（逗号分隔） |
| `--dry-run` | 只打印 key / MIME |
| `--json` | 结束后把结果数组打到 stdout |

上传成功后，把返回的完整 `url` 写入组件 metadata 的 `html_url` / `css_url` 等（用下面的 `cms`）。脚本**不会**自动改 CMS。

## 4. 组件与页面 `cms.mjs`

`type` 是表字段：组件 create 必须 `--type`；页面 create 必须 `--type`（`general` / `list` / `postsingle` / `productsingle`）。不要把 `type` 放进 `--metadata-json`，脚本会删掉 metadata 里的 `type` 键。

编码仅字母数字：`^[a-zA-Z0-9]+$`。

metadata **整份替换**。只改几个键时加 `--merge`（先读静态 JSON 再合并）。静态 JSON 有几秒延迟，刚写入后立刻 `--merge` 可能读到旧数据。

### 组件

```
node scripts/cms.mjs component list
node scripts/cms.mjs component get --code hero01
node scripts/cms.mjs component create --code hero01 --type static --metadata-json "{...}"
node scripts/cms.mjs component update --code hero01 --merge --metadata-json "{\"css_url\":\"https://tenantdoc.gt6ai.xyz/.../hero01.css\"}"
node scripts/cms.mjs component delete --code hero01
```

壳子块可加 `--parent-code header01`（写入 `parent_id`，渲染仍靠 HTML 里的 `{{code}}`）。

### 页面

```
node scripts/cms.mjs page list
node scripts/cms.mjs page get --code home
node scripts/cms.mjs page create --code login --type general --metadata-json "{...}"
node scripts/cms.mjs page update --code login --merge --metadata-json "{\"title\":\"Log in\"}"
node scripts/cms.mjs page delete --code about
```

固定页码（`login`、`cart`、`dashboard` 等）见 [page契约.md](./page契约.md) 第 2 节，不要改名。

### 关联

```
node scripts/cms.mjs link list --page home
node scripts/cms.mjs link add --page home --component hero01 --sort 10
node scripts/cms.mjs link update --page home --component hero01 --sort 12
node scripts/cms.mjs link remove --page home --component hero01
```

关联 metadata 只放本页覆盖（文案、`article_id`、`template_id`）。不要在关联里再抄一份 `html_url`。

建议 `sort_order`：layout `1`，header `2`，pageheader `5`，正文 `10`，footer `20`。

---

## 5. 典型顺序

改一套皮并挂到页面：

1. 本地改 `website/{type}/{code}/` 下的文件
2. `node scripts/upload.mjs --dir website/{type}/{code}`
3. 用返回 URL 更新组件：`cms component update --code … --merge --metadata-json …`
4. 新组件才 `cms component create --code … --type …`
5. 需要出现在某页时 `cms link add --page … --component … --sort …`

不要把 `website/vendor/` 拷到业务租户。本库租户维护 vendor 时，可以上传 `website/vendor/`。

---

## 6. Windows

PowerShell 里用 `;` 连接命令，不要用 bash 的 `&&`。`--metadata-json` 的引号在 PowerShell 里容易坏，改用 `--metadata-file path.json`。
