# moban 流程与步骤

本文是 **moban 空模板 + 组件库** 的实施计划。只在本项目推进，不改 a0005 及其他套模板。文档只写在 `moban/docs/`，后续 Skill 也从这里生成。

已完成的前置（不再列入步骤）：

- 空壳 Astro 内核（从 a0005 拷入，去掉 Tailwind 构建）
- `public/assets/theme.css` 仅作主题文件样例，**不**由内核自动注入；正式主题走 layout 组件 URL
- token 与 a0005 色板对照（换肤时填值，不扩变量名）

原则（全程有效）：

- 组件可跨页、跨项目，是因为消费同一套 token、遵守同一套类型契约，不是零依赖。
- 全局只有 token，没有 `.btn` / `.container` / Tailwind / Bootstrap。
- 每个组件自带语义 HTML + 独立 CSS + 可选 JS；HTML 里不出现 utility class。
- 动态类型保留 `{{占位符}}` 与 `data-*` 钩子；改的是皮，不是契约。
- 每步先改契约与文档，再改内核，再收第一批组件。用户确认后再进入下一步。
- 组件的 HTML / CSS / JS / 媒体**只放在该组件自己的目录**，不按页面、不按旧的 `html/a0006/` 散落。公网根为 `https://tenantdoc.gt6ai.xyz/{租户id}/website/`。

## 1. 修改组件与页面的定义

目标：内核用 **类型** 决定怎么渲染，不再用 `components_code` 的名字去猜；页面只负责 **挂哪些组件、什么顺序、本页覆盖哪些文案/数据**，不再在页面上「再定义一遍组件」。

### 1.1 组件增加类型，不再用名称断言

**现状问题**

内核现在靠名字分流，例如：

- `components01–99` → 静态 HTML
- `post` / `post01–99` / `blog*` → 文章区块
- `postlist` / `bloglist` → 列表
- `headerhtml` / `footerhtml` → 头底壳

换一个稳定 ID（如 `hero-split`、`blog-grid`）就会认不出来。组件库无法用职能命名。

**要改成**

每个组件必须有显式 `type`（或同等字段，字段名本步冻结）。`components_code` 只是实例 ID，可以叫任何稳定名字。

建议类型清单（本步定稿，后续步骤按此实现）：

| type | 谁来渲染 | 说明 |
|------|----------|------|
| `layout` | 不进正文，Layout 注入 CSS/JS | 全局样式，即主题层 |
| `header` | 头部壳 | 内嵌 `{{子组件code}}` |
| `footer` | 底部壳 | 同上 |
| `chrome` | 头/底子块 | logo、nav、语言、购物车等，不单独挂到页面正文 |
| `static` | 静态 HTML 插槽 | Hero、特性、CTA 等，无服务端数据契约 |
| `post` | 动态文章/产品预览 | 首页/落地页区块 |
| `postchild` | 当前文章的下级列表 | 须挂在详情页；按 has_children / child_article_ids |
| `postlist` | 列表网格 | 须挂在列表型页面 |
| `listfilter` | 列表筛选 | 须与 `postlist` 同页 |
| `pageheader` | 内页页头/面包屑 | |
| `markdown` | 远程 Markdown 正文 | 隐私政策等文档页；页面只挂组件 |
| `postsingle` | 文章详情 | 须挂在文章详情路由 |
| `productsingle` | 产品详情 | 须挂在产品详情路由 |
| `form` | 表单 | 需内容模板 id |
| `pricing` | 订阅套餐 | |
| `login` / `signup` | 登录/注册 | 成功后看租户 `metadata.email_verify` |
| `verifyemail` | 邮箱 OTP 验证 | 页码 `verifyemail`，URL `/verifyemail` |
| `cart` / `wishlist` | 购物车/愿望清单 | |
| `checkout` / `subscriptioncheckout` | 结账 | |
| `dashboard` | 会员中心壳 | 页面关联壳；子块用 `{{code}}` |
| `dashboardpanel` | 会员中心子块 | **不要**挂到页面，嵌在 dashboard 壳里 |

内核注册表改为：`type → Astro 实现`。名字不再进入 `isPostSectionCode(/^post\d*/)` 这类正则。

兼容：旧数据没有 `type` 时，可保留一层「按旧名字推断 type」的迁移表，只用于读旧租户，新组件禁止再靠名字。

**本步交付**

- `docs/契约-组件类型.md`：类型枚举、每个 type 的必填 metadata、禁止事项
- 内核：`getSectionComponent` 改为读 `type`；展示字段以 1.4 为准
- 验收：名为 `hero-split`、`type=static` 的组件能渲染；名为 `blog-grid`、`type=postlist` 的组件走列表实现

### 1.2 页面仅关联组件，不再在页面部分定义组件

**现状问题**

现在「定义」散落三处，经常互相拷贝：

1. 组件自身 metadata（`html_url` / `css_url` / 行为配置）
2. 页面-组件 **关联行** metadata（可整份覆盖，常把 HTML/CSS 又写一遍）
3. 页面 metadata（`htmlcode`、`markdowncode`、`css_url` 等，页面自己又像一个组件）

同一套皮改三次，组件库无法「一处定义、到处挂」。

**要改成**

| 层 | 只允许有 | 不允许有 |
|----|----------|----------|
| 组件 | `type`、默认 HTML/CSS/JS、该类型的默认行为 | 页面 URL、SEO |
| 关联 | `components_code`、`sort_order`、**本页实例覆盖**（文案、`template_id`、`article_id`、`list_path` 等） | 再写一份 `html_url` / `css_url`（除非本页明确换皮，且文档写明这是例外） |
| 页面 | `page_code`、页面表字段 `type`（`general` / `list` / `postsingle` / `productsingle`）、SEO、可选 `main_class` | 组件的 HTML/CSS/JS；不要在页面里「发明」一个组件；**不要**把页面 `type` 写进 metadata |

关联覆盖的默许范围（本步写进契约）：

- 允许：多语言文案、数据 id、列表路径、是否显示某块
- 默认不允许：换 HTML/CSS/JS（换皮去改组件，或换另一个组件挂上）

页面 markdown/html 正文**不要**写在页面 metadata（禁止 `content` / `content_en` / `markdowncode` / `htmlcode`）。改用 `type=markdown` 组件关联，见 [契约-组件类型/markdown.md](./契约-组件类型/markdown.md)。联系我们页挂 `type=form`，见 [契约-组件类型/form.md](./契约-组件类型/form.md)。登录 / 注册页见 [login.md](./契约-组件类型/login.md)、[signup.md](./契约-组件类型/signup.md)。邮箱验证页见 [verifyemail.md](./契约-组件类型/verifyemail.md)。购物车 / 愿望清单见 [cart.md](./契约-组件类型/cart.md)、[wishlist.md](./契约-组件类型/wishlist.md)。一次性结账 / 订阅结账见 [checkout.md](./契约-组件类型/checkout.md)、[subscriptioncheckout.md](./契约-组件类型/subscriptioncheckout.md)。会员中心见 [dashboard.md](./契约-组件类型/dashboard.md)。订阅套餐见 [pricing.md](./契约-组件类型/pricing.md)。

**本步交付**

- [page契约.md](./page契约.md)：页面职责、固定页码、页面 `type` 与四种布局
- 内核：渲染仍合并关联 metadata，但 Skill/工具规程改为「先改组件，页面只挂」
- 验收：新建一页只提交关联列表（code + sort + 少量实例字段），不传 `html_url`，页面能显示组件库里的皮

### 1.3 资源位置：以组件为核心

所有展示资源（HTML、CSS、JS、图片/字体/视频等媒体）按 **组件类型 + 组件名称** 存放，不再按页面目录、也不再使用 a0005 的 `html/a0006/{随便一个文件夹}`。

**公网 URL**

```
https://tenantdoc.gt6ai.xyz/{租户id}/website/{组件类型}/{组件名称}/{资源类}/{文件名}
```

| 段 | 取值 | 说明 |
|----|------|------|
| 租户 id | UUID | `r2_upload` 自动加前缀，传 directory 时**不要**自己拼 |
| 组件类型 | 与 1.1 的 `type` 相同 | `layout`、`static`、`header`、`postlist` … |
| 组件名称 | 即 `components_code` | 稳定 ID，如 `default`、`hero-split`、`blog-grid` |
| 资源类 | 固定四类 | `html` / `css` / `js` / `media` |
| 文件名 | 自定，含扩展名 | 建议带语言或版本：`hero-split_en.html`、`theme.css` |

另有一类**不是组件**的共享库目录（多组件共用的 Swiper 等），与 type 并列：

```
https://tenantdoc.gt6ai.xyz/{moban库租户id}/website/vendor/{库名}/js/{文件}
https://tenantdoc.gt6ai.xyz/{moban库租户id}/website/vendor/{库名}/css/{文件}
```

`vendor` 不进页面关联、不进类型注册表；只被组件 `depends` 引用。

**vendor 固定在 moban 库租户，建站时默认不拷贝**

- 共用库放在 **moban 项目自己的租户**（库租户）下，路径如上。文件稳定、很少改。库租户 id 以 moban 项目档案 / `src/config/app.ts` 为准，Skill 与内核都读这一处，不要每个站点再抄一份 UUID。
- 用户或 AI **复制组件到业务租户**时：拷的是该组件自己的 `html/css/js/media`。`depends` 仍指向库租户上的 vendor URL，**不要**把 `website/vendor/` 拷到业务租户，也不要改成业务租户路径。
- 仅当用户要**自己改或重定义**这份库时，才拷到业务租户 `website/vendor/{库名}/`，并把该组件（或该站）的 `depends` 改成新的完整 URL。未改之前，全站继续用库租户地址。
- 这是「禁止引用其它租户 URL」的**唯一常规例外**：vendor 允许、且应当指向 moban 库租户。组件自己的图、字体、皮文件仍必须是**当前业务租户**（或复制后的）地址。

**上传时的 directory**（不含租户 id）：

```
website/{组件类型}/{组件名称}/{资源类}
```

例：上传 `hero-split_en.html` → `directory: "website/static/hero-split/html"`。

**目录树（同一组件）**

```
{租户id}/website/
  vendor/{库名}/js|css|media/     仅 moban 库租户；业务租户默认不建这一层
  {type}/{name}/
    html/     语义 HTML（多语言分文件）
    css/      该组件自己的 CSS
    js/       该组件自己的 JS（含 init 与要提到文档级的脚本）
    media/    该组件引用的图、字体、视频
```

组件自己的脚本**仍放在该组件 `js/` 下**。「全局」指注入到 Layout（整页一次），不是把文件挪出组件目录。只有 `vendor/` 可以离开某个业务组件。

**layout（全局样式 / 全局 JS）**

全局资源也走组件：类型为 `layout`，用「组件名称」区分不同主题或脚本包。内核通过 layout 组件加载这些 URL。

```
https://tenantdoc.gt6ai.xyz/{租户id}/website/layout/{组件名称}/css/theme.css
https://tenantdoc.gt6ai.xyz/{租户id}/website/layout/{组件名称}/js/xxx.js
https://tenantdoc.gt6ai.xyz/{租户id}/website/layout/{组件名称}/media/font.woff2
```

不同全局风格 = 不同的 layout 组件名称（如 `default`、`a0005`），不要把两套 CSS 堆在同一个名称下互相覆盖。layout 的 `css_url` / `css_urls` / 脚本 URL 必须指向上述路径，而不是站点 `/assets/main.css`。

layout 只放**主题**（token、极少全站脚本）。不要把 Swiper、购物车 store 塞进 layout，否则又变回每页一份大 `main.js`。

**其它类型同样规则**

```
…/website/static/hero-split/html/hero-split_en.html
…/website/static/hero-split/css/hero-split.css
…/website/static/hero-split/media/hero.jpg

…/website/header/default/html/header_en.html
…/website/chrome/nav-primary/html/nav_en.html

…/website/postlist/blog-grid/html/blog-grid_en.html
…/website/postlist/blog-grid/css/blog-grid.css
…/website/postlist/blog-grid/js/blog-grid.js
```

**本页脚本怎么进 Layout（不要全库预挂）**

Astro SSR 时已经知道本页有哪些组件。内核扫描 **本页会渲染的组件树**，不是租户下全部组件：

1. 本页关联的组件
2. `header` / `footer` 壳 HTML 里的 `{{子组件}}`（子块不在页面关联里，但会渲染）
3. 租户 `layout` 组件（每页都有）

从这棵树上收集 `depends` 与 `global_js`，按 URL 去重后注入 Layout。本页树里没有的组件，其 JS **不上页**。

注入顺序：

```
layout 的 CSS/JS
→ depends 解析出的 vendor（去重）
→ 各组件 global_js（去重）
→ 各组件 HTML 旁的 init_script_url（跟区块，可出现多次）
```

`global_js` 与 `init_script_url` 不要混用：购物车状态、必须先于多个区块的脚本用 `global_js`；只绑本区块 DOM 的用 `init_script_url`。

**硬性约定**

- 组件 metadata 的 `html_url` / `css_url` / `init_script_url` / `global_js` 只填**完整公网 URL**；前三者与 `global_js` 须落在**该组件所属租户**的组件目录。`depends` 默认解析到 **moban 库租户** 的 `website/vendor/{库名}/`，不要解析成当前业务租户。
- HTML/CSS 里的图片、字体一律用本组件 `media/` 的完整 tenantdoc URL，禁止 `/images/…`、`./images/…`、站点域名相对路径。禁止引用**其它业务租户**的皮文件；vendor 指向库租户除外。
- **禁止**在 `website/` 下建页面目录（不要 `website/home/…`）。页面没有自己的 HTML/CSS；正文也是某个组件。
- **禁止**把 A 组件的图放到 B 组件的 `media/`，或把全局 CSS / vendor 塞进某个 static 组件，或把 vendor 塞进 layout。
- **禁止**建站时把 `website/vendor/` 整目录拷进业务租户「以防万一」。未声明要改库，就沿用库租户地址。
- 内核自带文件（如编辑态 `gt6-edit-mode.css`）仍可放在站点 `/assets/`，与租户组件资源分开；**主题 token 与组件皮不放内核目录作为正式来源**。
- 改文件建议换新文件名再改 metadata 指向，避免 CDN 缓存；确认后再删旧文件。

### 1.4 组件 metadata 字段表

组件记录上的展示与脚本字段（关联行默许覆盖的只有文案/数据 id，见 1.2；下表带「皮」的字段默认写在**组件自身**）。各 `type` 的业务字段（如 `template_id`、`list_path`）在步骤 5 的分文档里补，不在此发明。

| 字段 | 必填 | 写在哪 | 含义 |
|------|------|--------|------|
| `type` | 是 | 组件 | 1.1 的类型，内核靠它选渲染器 |
| `bare` | 否 | 组件 | `true` 时全宽、无额外包裹 |
| `translations[]` | 多语言时是 | 组件 | 按 `language_code` 分发下面的 URL |
| `html_url` / `html` | `static` / 有皮的类型是 | 组件 | 展示 HTML；外链须在本组件 `html/` |
| `css_url` / `css_urls` | 有样式时是 | 组件 | 本组件 CSS；须在本组件 `css/`。layout 的主题 CSS 也走这两字段 |
| `init_script_url` / `init_script` | 否 | 组件 | **区块级** init，跟在该组件 HTML 后加载，可每实例一次 |
| `global_js` / `global_script_urls` | 否 | 组件 | **文档级**脚本 URL 数组。本页组件树包含该组件时，提到 Layout，按 URL 去重，整页一次 |
| `depends` | 否 | 组件 | 共享库 id 数组，如 `["swiper"]`。默认解析为 `https://tenantdoc.gt6ai.xyz/{moban库租户id}/website/vendor/{id}/js/{id}.js`（及同目录约定 css）。本页有任一组件声明则加载一次。用户 fork 后可改为业务租户上的**完整 URL** |

`components_code` 是组件主键（名称），不是 metadata 里的字段。

**`init_script_url` vs `global_js` vs `depends` vs layout**

| | 文件位置 | 何时加载 | 次数 |
|---|----------|----------|------|
| `init_script_url` | `website/{type}/{name}/js/` | 该区块渲染后 | 本页有几处该组件就几次 |
| `global_js` | 同上（仍在该组件 `js/`） | Layout，仅当本页树包含该组件 | 每个 URL 一次 |
| `depends` | `website/vendor/{id}/js/`（默认在 **moban 库租户**） | Layout，仅当本页树有人声明 | 每个 vendor 一次 |
| layout 脚本 | `website/layout/{name}/js/` | 每页 Layout | 一次（主题，不是业务组件） |

示例（组件自身 metadata）：

```json
{
  "type": "static",
  "bare": true,
  "depends": ["swiper"],
  "global_js": [
    "https://tenantdoc.gt6ai.xyz/{tenant_id}/website/static/hero-split/js/hero-store.js"
  ],
  "translations": [
    {
      "language_code": "en-US",
      "is_primary": true,
      "html_url": "https://tenantdoc.gt6ai.xyz/{tenant_id}/website/static/hero-split/html/hero-split_en.html",
      "css_url": "https://tenantdoc.gt6ai.xyz/{tenant_id}/website/static/hero-split/css/hero-split.css",
      "init_script_url": "https://tenantdoc.gt6ai.xyz/{tenant_id}/website/static/hero-split/js/hero-split.js"
    }
  ]
}
```

关联行不要重复抄上述 URL；本页只需挂 `hero-split`。头里嵌了带 `global_js` 的 chrome 子块时，扫描壳模板即可，不必把子块再关联到页面正文。示例里 `depends: ["swiper"]` 解析到 **moban 库租户** 的 vendor，即使 `html_url` 已是业务租户上的拷贝。

**本步交付（1.1～1.4 一起）**

- `docs/契约-组件类型.md`：类型枚举 + 本表
- `docs/契约-页面与关联.md`：三层职责、关联可覆盖字段白名单
- `docs/契约-资源路径.md`：URL 模板、vendor 在库租户且建站不拷贝、按页收集 `global_js` / `depends`、禁止项
- 内核：`getSectionComponent` 读 `type`；Layout 按本页组件树注入 vendor + `global_js`
- Skill/上传规程按 `website/{type}/{name}/{html|css|js|media}` 与 `website/vendor/{id}/…` 写，不再写 `html/a0006/`

**步骤 1 完成标准**

类型能驱动渲染；页面 JSON 里看不到组件皮的完整定义；新上传的资源都落在 `website/{type}/{name}/…` 或 `website/vendor/…`；本页未使用的组件其 `global_js` / `depends` 不出现在 HTML 里。未完成前不要开始做具体组件皮。

## 2. 实现全局组件（layout / 主题）

对应类型：`layout`。这就是主题层，不是「再做一个 Bootstrap」。

**做**

- `layout` 只注入 CSS/JS，不进 body
- 主题文件放在该 layout 组件目录，例如：
  `…/website/layout/theme01/css/theme.css`、
  `…/website/layout/theme01/js/xxx.js`
- CSS 内容仍是 reset + 已冻结的 token（色/字/版心/间距/圆角/按钮变量）
- 换「a0005 皮肤」= 另建 layout 组件（如名称 `a0005`）换 token **值**，或改同一组件下的 css 文件；不换变量名、不加 `background-1…14`
- 不引入 Tailwind / Bootstrap；不定义 `.btn`、`.container`

**多个 `type=layout` 时加载哪一个**

库里可以有很多主题（`theme01`、`theme02`…），一次请求只注入一套。

选择顺序（没有第三档）：

1. **本页关联了 `type=layout` 的组件** → 用它（多份时取 `sort_order` 最先的一份）。关联只为选主题，**仍不在 body 里渲染**。
2. **本页没有关联任何 layout** → 加载 `components_code` 为 `layout` 的组件。
3. **2 也不存在** → 不加载任何 layout CSS/JS，**不回退**到 `/assets/theme.css` 或其它主题。

全站统一主题：不给每页关联 layout，只保留一个 code=`layout` 的组件即可。某一页换肤：只给该页关联 `theme01` 这类 layout。

**不做**

- 不在这一步做 Hero、头底、列表皮
- 不把其它类型组件的 CSS 打进 layout

**本步交付**

- `docs/组件-layout.md`（Skill 可读：何时改 token、禁止加变量、资源路径）
- 内核按「本页关联的 type=layout → 否则 code=`layout` → 否则不加载」注入 CSS/JS
- 验收：页关联 `theme01` 时注入的是 theme01；未关联且存在 code=`layout` 时用 layout；两者都没有则页面无主题 CSS

---

## 3. 实现静态组件

对应类型：`static`。

**做**

- 取消 `components01–99` 编号限制；ID 按职能：`hero-split`、`features-grid`、`cta-band`
- 每个组件：语义 HTML（en/cn）+ 根 class 下的独立 CSS + 可选 JS
- 文件落在 `website/static/{名称}/html|css|js|media/`
- CSS 只引用 token；选择器全部挂在自己的根 class 上
- 可挂到任意展示页，无 `page_type` 限制

**建议先收的第一批（验证合同，不要一次收 65 个）**

1. 一个 Hero
2. 一个特性/图文
3. 一个 CTA

从 a0005 对照视觉 **重写** class，禁止把 Tailwind utility 展开成「假独立 CSS」。

**本步交付**

- `docs/组件-static.md`：入库标准、命名、文件约定（html/css/js/media）
- 至少 3 个可挂样例组件
- 验收：同一 Hero 挂到 `home` 与 `about`，只换关联文案，皮不变；只改 layout 组件的 token 能换肤

---

## 4. 实现头部、底部组件

对应类型：`header` / `footer` / `chrome`。

**做**

- 壳组件 HTML 用 `{{子组件code}}` 嵌套，与现在 chrome 模型一致
- 子块（logo、nav、语言、购物车、版权）是独立组件，`type=chrome`，**不出现在页面正文关联里**
- 页面只关联一个 `header` + 一个 `footer`（可按页换不同壳）
- 壳与子块各自使用 `website/header|footer|chrome/{名称}/…`
- 子块 CSS 同样独立、吃 token

**本步交付**

- `docs/组件-chrome.md`：壳与子块、哪些 code 允许嵌套、页面如何换头、资源路径
- 一套最小头底（logo + 一列 nav + 版权）
- 验收：不关联 header/footer 的页面无头底；关联后全站可换壳；导航链接改子块即可

---

## 5. 实现动态组件

对应上表其余 type。每种 type **一份内核实现**，库里可以有多套皮肤 HTML/CSS。

**约束**

- 类型与页面路由仍要匹配：`postlist` 挂列表页，`checkout` 挂结账页，不要靠名字，靠 type + `page_type`/路由
- HTML 必须保留该类型文档中的占位符与 `data-*`
- 皮肤文件在 `website/{type}/{名称}/html|css|js|media/`，不依赖 a0005 的 `main.css`

**建议实现顺序（契约从简到繁）**

1. `pageheader`、`form`
2. `post`、`postchild`、`postlist`、`listfilter`
3. `postsingle`、`productsingle`
4. `pricing`、`login` / `signup`、`verifyemail`
5. `cart` / `wishlist` / `checkout` / `subscriptioncheckout` / `dashboard`

每做一个 type：先写 `docs/组件-{type}.md`（字段 + 钩子表 + 皮肤文件约定），再改内核（已在步骤 1 接好 type），再收 1 套默认皮肤。

**本步交付**

- 每个已实现 type 一份组件文档
- 至少：`form` + `postlist` 两套能在空模板上跑通的皮肤
- 验收：换皮肤文件不改 type 逻辑；缺钩子的 HTML 在文档里被标为不合格

---

## 6. 组件库的实现

在 2～5 的组件都「能单个挂」之后，把它们收成库，而不是散落的租户文件。

**库在 tenantdoc 上的位置（与 1.3 同一套路径）**

```
{租户id}/website/
  vendor/{库名}/js|css|media/   ← 仅 moban 库租户；业务站树里通常没有这一层
  layout/{名称}/css|js|media/
  header/{名称}/html|css|js|media/
  footer/{名称}/html|css|js|media/
  chrome/{名称}/html|css|js|media/
  static/{名称}/html|css|js|media/
  markdown/{名称}/html|css|md|media/
  form/{名称}/html|css|js|media/
  login/{名称}/html|css|js|media/
  signup/{名称}/html|css|js|media/
  verifyemail/{名称}/html|css|js|media/
  cart/{名称}/html|css|js|media/
  wishlist/{名称}/html|css|js|media/
  checkout/{名称}/html|css|js|media/
  subscriptioncheckout/{名称}/html|css|js|media/
  dashboard/{名称}/html|css|js|media/
  dashboardpanel/{名称}/html|css|js|media/
  pricing/{名称}/html|css|js|media/
  postlist/{名称}/html|css|js|media/
  postchild/{名称}/html|css|js|media/
  postsingle/{名称}/html|css|js|media/
  productsingle/{名称}/html|css|js|media/
  …（每个 type 一层，下面是组件名称）
```

本仓 `moban/docs/` 只放契约；组件皮的源文件最终以 tenantdoc 为准。`vendor/` **只维护在 moban 库租户**。本地可有一份与业务组件结构镜像的开发目录；上传业务组件时 directory 必须是 `website/{type}/{name}/{html|css|js|media}`。上传与 CMS 写入用本仓 `scripts/`，见 [脚本.md](./脚本.md)。

**本步要定的规则**

- 稳定 ID、版本（改库默认全站更新，要冻结则锁版本）
- 业务租户 metadata：组件皮可以是本租户 URL（复制后的），`depends` 仍用库租户 vendor 地址。复制接口的改写范围、字段白名单、`fork_vendor` 见 [契约-组件复制.md](./契约-组件复制.md)
- 入库清单：type、根 class、token 依赖、是否限页面类型、资源目录是否符合 1.3
- 目录页：`docs/组件库.md`（AI 选组件只看这一份索引 + 各组件文档；文中写明 vendor 不拷贝）

**验收**

- 空模板 + 主题 + 从库里选 1 个头底 + 2 个静态 + 1 个 `postlist`，能拼出一页
- 同一组件 ID 能挂到另一个页面，不必复制 HTML 文件

## 7. 用户 / AI 做网站的标准流程

这是给「在空模板上建站」用的操作规程，将来直接收成 Skill。不要从 a0005 的 SKILL.md / workflows.md 拷过来改名字。

**建站流程（草案，本步写细）**

1. 收集需求（语言、是否文章、是否交易/订阅、货币），写入任务 summary
2. 配语言/货币；选定 layout 组件（换肤，不换正文组件）
3. 规划页面与每页组件清单（只写 ID + type + 顺序），用户确认
4. 从组件库挂或复制组件：先头底，再各页正文，再动态数据 id。复制见 [契约-组件复制.md](./契约-组件复制.md)：拷 `website/{type}/{编码}/`，把该前缀里的租户 id 换成当前租户；**不要拷 vendor**，也不要只替换 UUID
5. 改的是关联文案与数据，不是去页面 metadata 里贴 HTML
6. 最后改导航链接；逐页给出访问地址，确认后再下一页

**编辑流程（草案）**

- 改皮 → 改该组件 `website/{type}/{name}/` 下的文件 + 组件 metadata 的 URL（业务租户内的皮）
- 改本页文案/数据 → 只改关联
- 改全站颜色字体 → 只改该 layout 组件 `website/layout/{名称}/css/` 里的 token 文件
- 换区块 → 解绑旧组件、绑定库里另一个 ID
- 改共用库（少见）→ 用户明确要求后，才把 vendor 拷到业务租户并改 `depends` URL；否则动库租户会影响所有未 fork 的站点，须单独评估

**本步交付**

- `docs/skill-建站.md`（主 Skill 正文）
- `docs/skill-编辑.md`（改站 SOP）
- 与步骤 1～6 的契约文档互相链接，不重复粘贴字段表
